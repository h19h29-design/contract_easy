## 제안하는 구현 범위

1. 첫 대상은 원본 `공사표준계약서`. 기존 로그인·프로젝트 소유권 검사를 재사용한다.
2. 공사·기관·업체 공통정보를 입력하고, 문서별 항목과 초안을 비공개 프로젝트에 저장한다.
3. 원본에서 확인한 항목을 채워 미리보기·수정·다운로드를 제공한다. **사용자가 HWPX 필수를 확정했다.** 엑셀/PDF/DOCX로 대체해 완료 처리하지 않는다.
4. 사용자가 입력한 계약금액·날짜와 법적 판단값을 구분한다. 기존 XLSM의 비율·기간 수식이나 고정값을 승인 없이 서비스 규칙으로 가져오지 않는다.
5. 검증은 입력 누락/날짜/금액 문자열 보존, 사용자 간 접근 차단, 초안 재조회, 원본 대비 필드와 출력 배치, 브라우저 작성→다운로드 흐름을 포함한다.

실제 서비스 구현은 아직 시작하지 않았다. 설계 스킬의 구현 전 확인 단계이며,
HWPX 필수 요구에 맞춰 아래 작성 흐름과 검증 경계를 제안한다.
원본 전체 배포·Git 추가, 매크로 실행, 운영 DB 변경은 하지 않는다.

## HWPX 작성 흐름 제안

- 기존 프로젝트 상세에서 `계약서 작성`으로 진입한다. 첫 버전은 공사표준계약서 한 종류에 집중한다.
- 기관·업체·공사·계약정보 입력, 비공개 초안 저장/다시 열기, 항목 수정, 미리보기, `.hwpx` 다운로드를 연결한다.
- 화면에서 입력 항목을 수정하며 자유 배치 편집기는 만들지 않는다. 다운로드 후 한글에서 본문과 표를 편집할 수 있어야 한다.
- 원본에 있는 항목·문구·표 구성을 대조한 전용 HWPX 서식을 서버에서 채우는 방식을 권장한다. 원본 재사용 조건을 확인하고 XLSM→HWPX의 임의 일괄 변환은 하지 않는다.
- 대안인 Windows/Excel/한글 상시 자동화 방식은 설치·라이선스·실행 세션에 대한 운영 의존성이 생긴다. 첫 버전의 런타임에는 포함하지 않는다.
- 법적 비율·기간·계약방법을 추정하지 않는다. 사용자 입력값과 승인 규칙에서 나온 값을 구분하고, 미확정 항목을 자동 채우지 않는다. 검토 필요 표기와 다운로드 시 확인 절차를 둔다.
- 프로젝트 권한과 CSRF 검사를 재사용한다. 원본 자료와 개인별 작성 문서를 분리하며 작성 내용은 공개 corpus나 로그에 넣지 않는다.
- 생성 파일은 XML/ZIP 기반 실제 HWPX여야 하며 본문을 이미지로 넣거나 다른 문서의 확장자만 바꾸지 않는다. 원본 매크로·외부 연결·실제 인감 이미지는 포함하지 않는다.
- 웹 미리보기는 항목 확인용이며 한글의 실제 페이지 나눔과 동일하다고 보장하지 않는다. 한글에서 표·문단·긴 입력값·페이지 나눔을 별도로 검증한다.

## HWPX 검증 근거와 환경 확인

- 한컴 공식 포맷 설명: https://tech.hancom.com/hwpxformat/ (2026-09-12 확인).
  HWPX의 ZIP/XML 구조, 본문/서식 파일과 패키지 참조 구조를 확인했다. 이 개요만으로 생성기의 포맷 적합성을 보증하지 않는다.
- Mac `/Applications`, `/Users/mac-mini/Applications`의 2단계 앱 폴더 및 Windows `C:\Program Files\Hnc`, `C:\Program Files (x86)\Hnc` 아래에서 한글 앱/Hwp.exe를 찾지 못했다. 다른 경로에 설치돼 있지 않다는 의미는 아니다.
- 자동 검증: 패키지/XML 참조, 모든 입력값 왕복 추출, 특수문자·긴 한글·줄바꿈·누락 처리, 권한/API/DB 및 브라우저 다운로드 회귀.
- 실제 한글 검증: 파일 열기, 계약서 표·문구·인쇄 배치 확인, 수정 후 HWPX 재저장·재열기. 실제 한글 환경이 확인되지 않으면 이 항목은 미검증으로 보고하고 사용 가능 완료로 표시하지 않는다.
